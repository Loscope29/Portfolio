IA générative

Assistant RAG en ligne

Répondre à partir d’une base de documents, à toute heure.

Voir le dépôt

3clouds : AWS, GCP, Azure

Problème
Rendre une base de documents interrogeable en langage naturel, sans relire chaque fichier.
Approche
Collecte et indexation des documents, recherche des passages utiles, réponse générée par Amazon Nova 2 Lite via Bedrock.
Résultat
En ligne sur AWS Lambda, accès gérés avec IAM et coûts sous alerte, puis porté sur GCP et Azure.

Le contexte

Un assistant en ligne qui répond à toute heure à partir d’une base de documents : ici mon CV et des documents sur mon parcours, interrogés par des recruteurs.

C’est le schéma d’une base de connaissance interne : collecter les documents, les indexer, retrouver les bons passages, puis répondre en citant ce qui a été trouvé.

Les données

Mon CV et des documents collectés par scraping.

La démarche

  1. Collecte des documents et recherche des passages pertinents (RAG).
  2. Génération des réponses avec Amazon Nova 2 Lite via Amazon Bedrock, et avec l’API OpenAI.
  3. Mémoire des conversations conservée sur S3.
  4. Image Docker sur ECR, exécution sur AWS Lambda, interface statique sur S3.
  5. Accès gérés avec IAM, alertes de facturation pour maîtriser les coûts.
  6. Portage sur GCP (Cloud Run) et sur Azure (Container Apps).

Les résultats

  • 3clouds : AWS, GCP et Azure
  • 24 h/24en ligne, sans intervention

Les limites

  • Le modèle de génération est appelé sur le cloud : pour des documents internes confidentiels, la même chaîne se monte en local, avec un modèle ouvert et des embeddings calculés sur place, comme dans SemanticSearchAPI.

Les outils

  • Bedrock
  • Lambda
  • S3
  • Docker
  • IAM
