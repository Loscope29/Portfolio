SemanticSearchAPI

Une base de documents interrogeable par le sens, qui tourne en local.

Voir le dépôt

4routes d’API documentées

Problème
Retrouver un passage dans une pile de PDF sans connaître les mots exacts, ni envoyer les documents à un service tiers.
Approche
Extraction, découpage et indexation des PDF ; embeddings Sentence-Transformers calculés sur la machine, stockés dans PostgreSQL et pgvector.
Résultat
Une API Django REST sans appel à un service externe : elle indexe des PDF, cherche par similarité et propose des documents proches.

Le contexte

Un projet de master : une API de recherche sémantique qui indexe des documents PDF et répond selon le sens de la question, plutôt que sur des mots-clés.

Tout tourne sur la machine : le modèle d’embeddings MiniLM, la base PostgreSQL et l’API. Aucun document n’est envoyé à un service tiers, ce qui en fait une base possible pour un RAG hébergé en local.

Les données

Les documents PDF téléversés par l’utilisateur.

La démarche

  1. Téléversement d’un PDF par l’API et extraction de son texte avec PyMuPDF.
  2. Découpage du texte en segments, pour gagner en précision.
  3. Calcul d’un embedding par segment avec Sentence-Transformers (MiniLM).
  4. Stockage dans PostgreSQL avec pgvector, et un index ivfflat pour accélérer la recherche.
  5. Recherche par similarité cosinus, documents similaires et historique des recherches.
  6. API Django REST Framework documentée avec Swagger.

Les résultats

  • 4routes : téléversement, recherche, documents similaires, historique
  • ivfflatindex vectoriel pgvector pour accélérer la recherche
  • 0appel à un service externe : modèle et base en local

Les limites

  • Les PDF scannés ne sont pas encore lus : il faudrait un OCR.
  • Seul le format PDF est pris en charge pour l’instant.

Les outils

  • Django REST Framework
  • Sentence-Transformers
  • pgvector
  • PostgreSQL
  • PyMuPDF
